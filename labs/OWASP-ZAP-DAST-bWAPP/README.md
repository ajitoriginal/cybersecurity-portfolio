# Dynamic Application Security Testing (DAST) using OWASP ZAP on bWAPP

---

## 📌 Course Context

This lab was completed as part of my hands-on **Cyber Security / Application Security** learning journey, focusing on **Dynamic Application Security Testing (DAST)** and automated web application vulnerability assessment.

---

## 🎯 Objective

The objective of this lab is to configure **OWASP ZAP** and perform Dynamic Application Security Testing (DAST) against the vulnerable **bWAPP (Buggy Web Application)** deployed locally using **XAMPP**.

The lab demonstrates how a DAST tool can analyze a running web application, identify potential security weaknesses, review security alerts, and generate a detailed security assessment report.

---

## 📖 Overview

**Dynamic Application Security Testing (DAST)** evaluates an application while it is running by interacting with the application through HTTP requests and responses.

In this lab:

- bWAPP was deployed locally using XAMPP.
- The bWAPP database was configured using MySQL/phpMyAdmin.
- OWASP ZAP was installed and configured.
- An automated security scan was performed against the locally deployed application.
- ZAP alerts were reviewed.
- A security assessment report was generated.

The lab provides practical exposure to using **OWASP ZAP as a DAST tool** for identifying security weaknesses in a running web application.

## 🔬 Methodology

### 1. Deploy XAMPP

XAMPP was downloaded and installed on the Windows Server 2022 environment.

The XAMPP environment was used to provide:

- Apache web server
- MySQL database server
- phpMyAdmin database management interface

---

### 2. Deploy bWAPP

The bWAPP source code was downloaded and extracted.

The application files were copied into the XAMPP `htdocs` directory so that the application could be served through the local Apache web server.

```text
XAMPP
└── htdocs
    └── bWAPP
```

### 3. Configure the bWAPP Database

The `bwapp.sqlite` file was copied according to the lab setup.
Apache and MySQL services were started from the XAMPP Control Panel.
The phpMyAdmin interface was then accessed:

```
http://localhost/phpmyadmin
```

A new database named:

```
bWAPP
```

was created.
The required `bWAPP.sql` database script was then imported into the newly created database.

---

### 4. Verify bWAPP Deployment

After configuring the database, the bWAPP application was accessed through:

```
http://localhost/bWAPP/login.php
```

The application login page was successfully displayed, confirming that the vulnerable application was deployed and accessible through the local environment.

---

### 5. Install OWASP ZAP

OWASP ZAP was downloaded and installed on the Windows Server environment.
OWASP ZAP was then launched to perform the dynamic security assessment.

---

### 6. Configure Automated Scan

From the OWASP ZAP interface, the Automated Scan option was selected.
The deployed web application target was entered:

```
http://localhost
```

The **Attack** option was then selected to start the automated security scan.

---

### 7. Monitor the Security Scan

During the scan, OWASP ZAP crawled and tested the target application.
The scan interface displayed the requests and responses being processed while the assessment was in progress.
This demonstrated the dynamic nature of DAST, where the security tool interacts with the running application rather than analyzing only its source code.

---

### 8. Review Security Alerts

After the scan, the Alerts section in OWASP ZAP was opened.
The generated alerts provided information about security issues identified during the assessment.
The alerts can be used to understand:

- Security weaknesses
- Affected application components
- Risk levels
- Potential security impact
- Areas requiring further investigation

---

### 9. Generate Security Report

The **Report** option was selected from OWASP ZAP.
The report generation functionality was used to create a detailed security assessment report.
The generated report contained information about the scan, identified alerts, and security findings.

## 🔐 Security Relevance

DAST is an important component of an **Application Security** program because it evaluates applications in their running state.
It can help security teams identify vulnerabilities that may become exploitable through the application's exposed interfaces.
DAST can be integrated into a broader **Secure SDLC** alongside:

```
Secure Coding
      ↓
Code Review
      ↓
SAST
      ↓
DAST
      ↓
Vulnerability Management
      ↓
Remediation
      ↓
Retesting
```
